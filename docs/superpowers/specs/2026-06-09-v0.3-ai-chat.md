# v0.3：真 AI 聊天 + 人格蒸馏

日期：2026-06-09

## 版本定位

v0.3 把首页从「关键词模拟回复」升级为 **DeepSeek 驱动的真实流式对话**，并通过离线蒸馏的 Persona Brief 与既有 `personaRules` 约束回答语气与边界。

本版本的目标是：访客在首页获得一个**像你说话方式的 AI 分身入口**，能进行多轮对话，但不假装作者实时在线，也不检索站内内容。

v0.2.x 已完成 Sanity 内容后台、书影音体验与页面导航优化。v0.3 专注 AI 聊天链路，不改动内容模型与列表页行为。

## 产品原则

- 网站仍然是中文个人网站 / 个人博客，聊天是「对话入口」，不是独立 Chat 产品。
- UI 延续极简、温和、内容优先；不增加复杂会话管理界面。
- AI 以第一人称回应访客，身份是「站点里的 AI 分身」，不是作者本人。
- 人格边界由代码规则 + 环境变量 Brief 双重约束；Brief 与 API Key 不进公开 Git。
- 访客对话仅保存在浏览器 `sessionStorage`；服务端不持久化聊天记录。
- 不提前加入登录、用户绑定、跨设备同步、公开 RAG、私密 RAG。

## 已确认决策

| 项 | 决定 |
|----|------|
| LLM 厂商 | DeepSeek 官方 API（`https://api.deepseek.com`） |
| 默认模型 | `deepseek-v4-pro` |
| 思考模式 | 关闭（普通 chat，不用 reasoning） |
| Persona Brief | 环境变量 `PERSONA_BRIEF`（不进 Git） |
| 对话记忆 | 浏览器 `sessionStorage`，关标签页后清空 |
| 免责声明 | 仅 system prompt 约束，界面不重复（1A） |
| 存储裁切 | 与 API 上下文一致，保留最近 10 轮（2A） |
| 无 API Key | dev：`chatPresets` 模拟；production：明确报错 |
| 功能边界 | 仅真 AI + persona，不含 RAG |

## 范围总览

### v0.3 纳入

- `POST /api/chat` 服务端接口（SSE 流式）。
- DeepSeek OpenAI 兼容调用（`deepseek-v4-pro`）。
- Persona system prompt 构建（`personaRules` + `PERSONA_BRIEF`）。
- 首页 `ChatHome` 改为流式消费 API 响应。
- 多轮对话：`sessionStorage` 读写，刷新页面不丢失（同标签页内）。
- 上下文截断：最近 10 轮（20 条 message）发给 API。
- 输入/输出/限流 guardrails。
- dev 环境保留 `chatPresets` 模拟 fallback。
- Sidebar `/?prompt=` 与建议问题按钮行为保持不变。
- 单元测试 + E2E 更新。

### v0.3 不纳入

- 公开 RAG / 向量检索 / 来源引用。
- 登录、用户绑定、历史对话列表、跨设备同步。
- 私密蒸馏层（ChatGPT 历史、私人笔记等）。
- 聊天记录服务端持久化或数据库。
- 会话标题、删除会话、导出对话。
- 内容审核后台、人工审核队列。
- 移动端聊天 UI 专项改版（不破坏即可）。

## 用户可见行为

### 首页聊天

保留现有两态 UI：

1. **初始态**：居中开场「我们从哪里开始呢？」+ 输入框 + 建议问题。
2. **对话态**：发送后线程上移，输入框沉底，assistant 流式输出。

与 v0.2 差异：

- 回复来自 DeepSeek，不再是固定 520ms 后关键词匹配。
- 多轮对话在同标签页内可引用上文；刷新页面后历史仍在（`sessionStorage`）。
- 关闭标签页后历史清空。

### 建议问题与 Sidebar

- 首页 `prompt-row` 与 Sidebar `/?prompt=` 仍触发发送。
- 行为与手动输入一致，进入对话态并调用 API。

### 失败与降级

| 环境 | 条件 | 行为 |
|------|------|------|
| development | 无 `DEEPSEEK_API_KEY` | 使用现有 `getSimulatedReply` |
| production | 无 `DEEPSEEK_API_KEY` | 返回 503 + 友好中文错误，前端展示提示 |
| 任意 | API 超时/5xx | 温和错误文案，不暴露堆栈 |
| 任意 | 输入超长 / 限流 | 400 / 429 + 前端提示 |

界面**不**在每条回复末尾重复免责声明；边界写入 system prompt。

## 人格与蒸馏

### 两层人格

1. **硬规则**（`src/data/persona.private.ts` → `personaRules`）  
   进 Git，含：第一人称、第二人称称呼访客、边界列表、语气标签、私密材料策略占位。

2. **软风格**（环境变量 `PERSONA_BRIEF`）  
   不进 Git，由作者离线撰写（建议 800–1500 字）：站点定位、推荐习惯、表达偏好、禁忌话题。

### System prompt 构建

服务端 `buildPersonaPrompt()` 合并：

- 身份说明：AI 分身，非作者实时在线。
- `personaRules` 边界与语气。
- `PERSONA_BRIEF` 全文（若为空则使用简短占位说明，并在 dev 日志 warn）。

### 回答约束（写入 prompt）

- 访客称「你」，AI 称「我」。
- 不假装作者实时在线，不替作者做现实承诺。
- 不知道时明确承认；不编造站内未发布内容。
- 不引用、泄露 `PERSONA_BRIEF` 原文或 hidden 配置。
- v0.3 无 RAG：不应假装「刚读过某篇随笔」；可一般性引导访客去 `/essays`、`/reviews` 浏览，但不得捏造具体篇名。

## 技术架构

```txt
浏览器 ChatHome
  ├─ 读/写 sessionStorage（messages[]）
  └─ POST /api/chat（Accept: text/event-stream）
        ├─ guardrails（长度、限流）
        ├─ buildPersonaPrompt()
        ├─ DeepSeek chat/completions（stream: true）
        └─ SSE 转发 delta.content
```

### 模块划分

| 路径 | 职责 |
|------|------|
| `src/pages/api/chat.ts` | HTTP 入口、SSE、环境判断 |
| `src/lib/chat/persona.ts` | `buildPersonaPrompt()` |
| `src/lib/chat/llm.ts` | DeepSeek 客户端、流式读取 |
| `src/lib/chat/guardrails.ts` | 输入校验、IP 限流 |
| `src/lib/chat/session.ts` | sessionStorage 键名、读写、截断（前端用） |
| `src/components/ChatHome.astro` | UI + 流式渲染 + storage |
| `src/data/chatPresets.ts` | dev fallback（保留） |
| `src/data/persona.private.ts` | 硬规则（已有） |

### API 契约

**请求** `POST /api/chat`

```json
{
  "messages": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}
```

- 仅接受 `user` / `assistant` 角色。
- 服务端忽略客户端传来的 `system`；system 由服务端注入。
- 服务端截断至最近 10 轮再转发 DeepSeek。

**响应** `text/event-stream`

- 每个 chunk：`data: {"content":"..."}\n\n`
- 结束：`data: [DONE]\n\n`
- 错误：非 200 时 JSON `{ "error": "..." }`

### 环境变量

| 变量 | 必填 | 说明 |
|------|------|------|
| `DEEPSEEK_API_KEY` | production 必填 | DeepSeek API 密钥 |
| `DEEPSEEK_MODEL` | 否 | 默认 `deepseek-v4-pro` |
| `DEEPSEEK_BASE_URL` | 否 | 默认 `https://api.deepseek.com` |
| `PERSONA_BRIEF` | 否 | 人格蒸馏正文；为空则降级为 rules-only |
| `PUBLIC_APP_ENV` 或 `import.meta.env.DEV` | — | 区分 dev fallback |

`.env.example` 增加占位说明，不含真实密钥与 Brief 正文。

### Guardrails 默认值

| 项 | 值 |
|----|-----|
| 单条 user 输入上限 | 500 字 |
| 输出 max_tokens | 800 |
| 上下文轮数 | 10 轮（20 条） |
| 限流 | 10 次 / 分钟 / IP |
| API 超时 | 30 秒 |

限流可用内存 Map（Vercel serverless 实例内 best-effort）；文档注明非全局严格限流，但对个人站足够。

### sessionStorage

- 键名：`personal-site:chat:messages`
- 结构：`{ messages: ChatMessage[], updatedAt: string }`
- 写入时机：每条 assistant 流式完成后
- 读取时机：页面 load 时恢复 UI；发送前合并进 API 请求
- 截断：超过 10 轮时丢弃最早消息（与 API 一致）

## 与现有代码的关系

- **`ChatHome.astro`**：替换 `setTimeout` + `getSimulatedReply` 为 `fetch` SSE；保留 DOM 结构与 CSS 类名。
- **`chatPresets.ts`**：保留；dev 无 Key 时继续服务；production 不调用。
- **`persona.private.ts`**：扩展为被 `persona.ts` 导入；仍无公开路由。
- **E2E**：`homepage sends a simulated chat reply` 改为期望真实回复或 dev fallback 非空；不再断言「还没有接入真正的 AI」（production 有 Key 时）。
